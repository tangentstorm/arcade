## Direct edition (`direct/`) — playable

- **`direct/brickslayer_logic.gd`** is a GDScript port of the lesson code.
  - The `Sprite`/`Paddle`/`Ball`/`Brick` classes and the 10×5 brick wall (`x*39+8`, `y*22+30`, shade `5-y`, tested bottom-first).
  - Paddle velocity and friction, serve on ↑ with `paddle.velocity+0.25` and dy `-4`.
  - The lesson-05 collision math (`ticksToHLine`, `ticksToVLine`, `collide`, with corner hits treated as top or bottom).
  - Shade-stepping bricks, score +1 per hit, 3 spares, `level_init`/`game_reset`.
  - The Console/Screen state machine with `swap`/`scheduleSwap`: title, game, pause, clear (2 s), game over (3.5 s), congrats, high scores.
- **Integer positions.** Sprite positions are ints, rounded on every set, the way `offsetLeft`/`offsetTop` read back from the DOM. So, as in the browser, the 0.25 serve spin doesn't move the ball sideways. The ball only gains sideways speed from `parseInt(paddle.velocity * friction)` on a paddle hit.
- **`step`.** Each feature turns on at the lesson that introduced it. That is what lets the trail "Play this step" (see below). The arcade launches step 10, the full game.
- **`direct/game.gd`** draws the 400×300 `#console` at 2×. It uses the CSS colors for bricks, lake, and text, and the overlays use the recovered PNGs.
- **High scores.** `highscores.php` kept a server text file. Here it's a local list in `user://brickslayer_scores.cfg`, seeded with the lesson's example file (alice…jamie). The rules are the same: keep 100, return the top 10, show 5, and a score above the 10th-place score goes to name entry.

### Deliberate deviations
- **Tick rate:** 10 ms fixed. The original `setInterval(…, 1)` was clamped to about 10 ms by 2007 browsers.
- **Missing media:** see ASSETS.md. Paddle and ball are gray boxes, `dimgray.png` is a 50% gray fill, and the game-over and high-score titles show their alt text. Sounds are silent unless the mp3s are vendored later.
- **Name entry:** Enter in the name field also submits (the original had only the "go" button).
- **Sound mapping:** the `soundManager.play('hit'/'break'/'serve')` call sites weren't in the listings. `serve` plays on serve, `hit` on a shade change, and `break` when a brick is destroyed. Only `bounce` and `fall` are shown in the code.
- **Keys:** Esc opens the arcade PauseOverlay. T opens the code trail. R restarts when playing lessons 00–07, which have no restart path of their own.
- **Lessons before 08 keep their quirks.** In lesson 05 the ball freezes at the floor. In 06–07 it sits in the lake once the spares are gone, because the game-over screen arrives in 08.

## Code trail (`trail/`)

- **What it is:** a CodeTrail-style lesson stepper, modeled on tangentcode `CodeTrail.mts`. Each lesson is a "commit" and each recovered code block is a step. The cursor is shown as `lesson + block/1000`, like `CodeTrail.stepFor`.
- **`trail/trail_data.gd`** is generated by `source/gen_trail_data.py` from `source/lesson-code/`. Each block gets the prose that precedes it on the lesson page.
- **`trail/trail_cursor.gd`** handles prev and next across lesson boundaries.
- **`trail/trail.tscn`** shows the lesson list, notes, and read-only highlighted code, with Prev/Next and **Play lesson NN**. That button launches `direct/game.tscn` at that lesson's feature level, and T returns to the same trail position.
- **Reaching the trail:** press T in the game (the footer shows the hint).

Tests: `tools/test_brickslayer.gd` (run by `tools/smoke_headless.sh`).
